2025 LLM Year in Review
今天我们来聊聊 AI 圈的大神 Andrej Karpathy 最近发布的一篇重磅文章——《2025 年大语言模型年度回顾》。Karpathy 觉得 2025 年是 LLM 发展非常强劲且充满变数的一年，发生了很多让他都觉得有点意外的"范式转变"。
首先，让我们来看看模型训练技术栈的演变。在 2025 年初的时候，各家实验室的标配大概是这三步走：第一步是预训练（就像 2020 年的 GPT-2/3 那样），第二步是监督微调（SFT，大约在 2022 年的 InstructGPT 时期成熟），第三步是基于人类反馈的强化学习（RLHF，也是 2022 年左右）。这套组合拳一度是训练生产级 LLM 的黄金标准，用了好几年都挺稳的。
但是到了 2025 年，一个全新的主角登场了——它就是 RLVR，全称叫"来自可验证奖励的强化学习"（Reinforcement Learning from Verifiable Rewards）。这一步现在已经成了事实上的第四大标准阶段。这是个什么概念呢？就是让模型在一些可以自动验证结果的环境里（比如数学题或者编程谜题）去"刷题"训练。在这个过程中，模型会自发地发展出一种看似"推理"的策略——它学会了把大问题拆解成中间计算步骤，甚至学会了反复推敲、来回琢磨、自我修正的各种问题解决策略。你可以看看 DeepSeek R1 的论文，里面有很多具体的例子。这在以前的范式里是很难做到的，因为我们很难明确告诉模型什么样的推理路径和恢复策略才是最优的，但现在通过 RLVR，模型通过对奖励的优化自己找到了适合它的方法。
这就非常有意思了。你看，SFT 和 RLHF 其实都是相对较短的微调过程，从算力角度来说都不算太重。但 RLVR 不一样，它面对的是客观的、没法作弊的奖励函数，这就允许进行更长时间的优化。事实证明，RLVR 的性价比极高——每一块钱算力能换来的能力提升很可观，所以它开始大量吞噬原本打算用于预训练的算力。Karpathy 观察到，2025 年的能力提升主要就来自于各家实验室在消化这个新阶段的红利。虽然模型尺寸看起来没变大多少，但强化学习跑的时间变长了很多。而且特别独特的一点是，这还带来了一个全新的"旋钮"和相应的缩放定律——我们可以通过让模型生成更长的推理过程，也就是增加"思考时间"，在测试时动态换取更强的能力。OpenAI 的 o1（2024 年底发布）是这一路线的首次展示，但到了 2025 年初发布的 o3，那个拐点就非常明显了，你能直观地感受到质的飞跃。
说到对智能的理解，Karpathy 提出了一个非常生动的比喻。他说 2025 年是他第一次真正凭直觉理解了 LLM 智能的"形状"。他和整个行业都开始意识到，我们不是在"进化或培育动物"，我们是在"召唤幽灵"。你想啊，LLM 的方方面面都不一样——神经网络架构不同、训练数据不同、训练算法不同，特别是优化压力完全是两码事。所以我们得到的是智能空间里非常不同的实体，用"动物"的视角去理解它们是不合适的。从监督信息的角度来说，人类的神经网络是为了在丛林里让部落生存而优化的，而 LLM 的神经网络是为了模仿人类文本、在数学谜题里拿奖励、或者在 LM Arena 竞技场里讨人类点赞而优化的。因为可验证的领域允许 RLVR 训练，LLM 在这些领域附近的能力会"尖峰化"，所以它们整体表现出一种非常有趣的、参差不齐的性能特征——它可能同时是一个精通万物的天才博学家，又是一个困惑且认知能力有挑战的小学生，甚至下一秒就可能被一个越狱指令骗走你的数据。

Karpathy 还特别喜欢这张图（插图放在shownotes中了），因为它指出了人类智能其实也是参差不齐的，只是方式不同而已。
这也引出了他对基准测试（Benchmarks）的态度变化。坦白说，Karpathy 在 2025 年对各种跑分榜单普遍感到冷漠，甚至失去了信任。核心问题在于，基准测试本身几乎天然就是可验证的环境，这就意味着它们立刻容易被 RLVR 针对，或者被合成数据生成这种较弱形式的方法污染。在典型的"刷榜"过程中，各个实验室的团队不可避免地会构建一些环境，这些环境在嵌入空间里正好邻近基准测试占据的那些小区域，然后针对性地长出"尖峰"来覆盖它们。在测试集上训练已经成了一种新的艺术形式。所以现在的局面就是，你能看到模型在所有榜单上都碾压人类，但离真正的 AGI（通用人工智能）还差得远呢。Karpathy 还专门写了几篇文章深入探讨这些话题，包括《动物与幽灵》、《可验证性》和《心智空间》，有兴趣的朋友可以去看看。
接下来，我们聊聊应用层。Karpathy 认为 Cursor（除了它本身今年的用户暴涨之外）最值得注意的地方是，它令人信服地揭示了"LLM 应用"的新图层——现在大家都开始谈论"某某领域的 Cursor"。就像他今年在 YC 演讲里强调的那样，像 Cursor 这样的 LLM 应用会针对特定垂直领域打包和编排 LLM 调用，它们做了四件事：第一是上下文工程；第二是在后台编排多个 LLM 调用，把它们串成越来越复杂的有向无环图（DAG），并精细平衡性能和成本的权衡；第三是为人类提供特定应用的图形界面（GUI），让人能够参与到循环中；第四是提供一个"自主性滑块"，让用户决定放权多少。
2025 年大家花了很多口水在讨论这个新应用层到底有多"厚"。到底是 LLM 实验室会占领所有应用，还是 LLM 应用会有自己的生存空间？Karpathy 个人的看法是，LLM 实验室的趋势是培养出通用能力强的"大学毕业生"，而 LLM 应用则会把这些毕业生组织起来、微调、然后真正动员成特定垂直领域的专业团队，通过提供私有数据、传感器、执行器和反馈循环来实现。
说到具体的 Agent（智能体），Claude Code 是第一个让人觉得真正像样的 LLM Agent 展示——它能通过循环的方式，把工具使用和推理串联起来进行长程问题解决。另外 Claude Code 让 Karpathy 觉得特别值得注意的一点是，它运行在你的电脑上，使用你的私有环境、数据和上下文。他觉得 OpenAI 在这方面走弯路了，因为他们把早期的 Codex 和 Agent 的努力集中在从 ChatGPT 编排的云端容器部署上，而不是简单地用 localhost。虽然在云端运行的 Agent 集群感觉像是"AGI 的终局"，但我们生活在一个能力参差不齐、起飞速度足够慢的中间世界，把 Agent 直接运行在开发者的电脑上更有意义。注意，这里真正重要的区别不在于"AI 运算"本身是在云端还是本地运行，而在于其他所有东西——那台已经存在、已经启动的电脑，它的安装、上下文、数据、密钥、配置，以及低延迟的交互。Anthropic 把这个优先级搞对了，把 Claude Code 打包成了一个令人愉悦的、极简的命令行界面（CLI）形态，这改变了 AI 的样子——它不再只是一个你去访问的网站（像 Google 那样），而是一个"住"在你电脑上的小精灵或幽灵。这是一种全新的、独特的与 AI 交互的范式。
2025 年还有一个特别火的概念，就是 Karpathy 自己造的词——"Vibe Coding"（氛围编码或意念编程）。今年 AI 跨越了一个能力门槛，你可以直接用英语构建各种令人印象深刻的程序，甚至完全忘掉代码的存在。有意思的是，Karpathy 在一条"淋浴思考"的推文里随口造了这个词，完全没想到它会传播得这么远。有了 Vibe Coding，编程不再严格保留给受过高度训练的专业人士，而是任何人都能做的事。这又是他在《赋权于民：LLM 如何翻转技术扩散的剧本》那篇文章里写到的一个例子——跟之前所有技术形成鲜明对比的是，普通人从 LLM 中获益远远超过专业人士、企业和政府。但 Vibe Coding 不仅赋权给普通人去接触编程，它还赋权给受过训练的专业人士去写更多（用 Vibe Coding 写的）原本永远不会被写出来的软件。比如在 nanochat 项目里，Karpathy 用 Vibe Coding 写了一个高度高效的、用 Rust 实现的自定义 BPE 分词器，而不是去采用现有的库或者学到那个深度的 Rust。他今年 Vibe Coding 了很多项目，作为他想让某个东西存在的快速应用演示（比如 menugen、llm-council、reader3、HN time capsule）。他甚至还 Vibe Coding 了整个临时应用，就为了找一个 bug——因为为什么不呢，代码突然变得免费、短暂、可塑、用完即弃了。Vibe Coding 将会重塑软件领域并改变职位描述。
最后，Karpathy 盛赞了 Google 的 Gemini Nano Banana，称它是 2025 年最不可思议、最具范式转移意义的模型之一。在他的世界观里，LLM 是类似于 70 年代、80 年代计算机那样的下一个主要计算范式。因此，我们将会看到基于根本上相似的原因而产生的相似类型的创新。我们会看到个人计算的对应物、微控制器（认知核心）的对应物、互联网（智能体的互联网）的对应物等等。特别是在 UI/UX 方面，跟 LLM "聊天"有点像在 80 年代向计算机控制台发出命令。文本是计算机（和 LLM）的原始/偏好的数据表示，但它不是人们偏好的格式，尤其是在输入方面。人们其实不喜欢读文字——那很慢、很费力。相反，人们喜欢以视觉和空间的方式消费信息，这也是为什么传统计算发明了 GUI（图形用户界面）。同样地，LLM 应该用我们偏好的格式跟我们交流——图片、信息图表、幻灯片、白板、动画/视频、Web 应用等等。这方面早期和现在的版本当然是像 emoji 和 Markdown 这样的东西，它们是用标题、粗体、斜体、列表、表格等方式来"装扮"和视觉化布局文本，让它更容易消费。但谁真正会来构建 LLM GUI 呢？在这个世界观里，Nano Banana 就是这可能会是什么样子的第一个早期暗示。而且重要的是，它的一个显著特点是，这不只是关于图像生成本身，而是关于文本生成、图像生成和世界知识的联合能力，它们全都纠缠在模型权重里。
总的来说，2025 年是激动人心且有点出乎意料的 LLM 之年。LLM 正在作为一种新型智能出现,同时比 Karpathy 预期的要聪明得多，也愚蠢得多。无论如何，它们极其有用，他觉得这个行业连目前能力下 LLM 10% 的潜力都还没意识到。与此同时，还有太多想法可以尝试，从概念上讲这个领域感觉非常开放。就像他今年早些时候在 Dwarkesh 播客上提到的，他同时（而且表面上看似矛盾地）相信，我们既会看到快速且持续的进步，同时又还有大量工作要做。大家系好安全带吧！
