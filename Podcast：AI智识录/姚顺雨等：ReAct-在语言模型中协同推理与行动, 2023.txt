姚顺雨等：ReAct-在语言模型中协同推理与行动, 2023
今天我们来聊一聊ReAct这个框架的诞生。它的“历史地位”体现在， 从根本上提出了一个将 LLM（大型语言模型）从“静态知识库”转变为“动态行动者 (Agent)”的核心框架，使大型语言模型 (LLM) 能够以一种交错的方式，将推理 (Reasoning) 和行动 (Acting) 协同起来，以解决复杂的任务。当今几乎所有主流的 LLM Agent 开发框架（如 LangChain, LlamaIndex）都将 ReAct 作为最核心、最基础的 Agent 实现模式之一。无论是 OpenAI 开发的 GPTs（可以调用外部“Actions”）还是 Google 内部的 Agent 系统，其底层逻辑都遵循了 ReAct 提出的“（推理）思考”和“（工具）行动”相交错的范式。
总结来说，ReAct 的历史地位在于，将 LLM 从一个“博学的聊天者”升级为了一个可以在真实世界中执行复杂任务的“智能体”。
以下是详细内容：
1. 引言 (Introduction)
引言部分从人类智能的类比出发。人类的一个独特能力就是将面向任务的行动与语言推理（或内心独白）无缝结合 。我们在行动的间隙会用语言来跟踪进度（“菜切好了，该烧水了”）、处理异常（“没有盐了，改用酱油吧”）或意识到需要外部信息（“我该怎么和面？上网查一下”）。这种“行动”和“推理”的紧密协同，使人类能快速学习并稳健地做出决策 。
论文接着指出了现有 LLM 方法的局限性：
1.   纯推理 (Reason-Only) - 如思维链 (CoT)：
问题：CoT 是一种“静态黑盒”。模型的思考过程完全依赖其内部知识，无法与外部世界互动来更新其认知 。
后果：这导致了严重的“事实幻觉” (fact hallucination) 和“错误传播” (error propagation) 问题 。一旦推理链中某一步出错，后续步骤很可能全错 。
1.   纯行动 (Act-Only)：
问题：这类方法专注于将观察（observation）转换为文本，然后让 LLM 预测下一步动作 。
后果：它们通常缺乏对高级目标的抽象推理能力，也无法维护一个“工作记忆”来支持行动 。这导致模型在需要复杂规划或常识推理时表现不佳。
ReAct 的提出：
ReAct 作为一个通用范式被提出，旨在结合二者 。它通过提示 LLM 交错地生成推理轨迹和行动，允许模型：
•   (Reason to Act)：执行动态推理，以创建、维护和调整高级行动计划 。
•   (Act to Reason)：与外部环境（如维基百科）交互，并将获得的新信息融入到后续的推理中 。
2. ReAct 框架：协同推理 + 行动
ReAct 的思想很简单：它将智能体的行动空间从单纯的 \mathcal{A} (任务动作) 扩展到了 \hat{\mathcal{A}} = \mathcal{A} \cup \mathcal{L}，其中 \mathcal{L} 是语言空间 。
•   “思想” (Thought) 作为一种行动：当智能体选择一个 \mathcal{L} 空间中的动作时，这个动作被称为“思想” (thought) 或“推理轨迹” (reasoning trace) 。
•   思想的作用：它不会影响外部环境 ，而是用于在当前上下文中进行推理，并更新上下文 c_{t+1} = (c_t, \hat{a}_t)，以支持未来的推理或行动 。
•   思想的类型：这些“思想”非常灵活，可以用于：
◦   分解任务并制定行动计划  (例如，"我首先需要找到A，然后用A去打开B")。跟踪进度和调整计划 (例如，"A已经找到了，接下来我需要去B")。
◦   处理异常  (例如，"搜索A失败了，我需要换个关键词搜索A的别名")。
◦   注入常识 (例如，"胡椒瓶最可能在橱柜或台面上")。
◦   提取关键信息  (例如，"观察结果显示A在1844年成立")。
实现方式：
ReAct 主要通过少样本提示 (few-shot in-context examples) 来实现 。研究人员为 PaLM-540B 提供了几个人工编写的、包含“思想-行动-观察”序列的任务解决轨迹 。
论文还区分了两种任务类型下的不同提示策略：
1.   知识密集型任务 (如 HotpotQA)：采用交替生成模式。模型被严格提示按顺序生成“思想 (Thought) \rightarrow 行动 (Act) \rightarrow 观察 (Obs)” 。
2.   决策制定任务 (如 ALFWorld)：采用稀疏（sparse）或异步模式。模型可以自己决定何时需要“思考” ，何时只需要连续执行动作 。
3 实验 1：知识密集型推理任务 (HotpotQA, Fever)
在这部分，模型需要回答多跳问题 (HotpotQA) 或进行事实核查 (Fever) 。
•   环境设置：模型没有预先访问支持文档 。它必须主动通过一个简单的维基百科 API 来获取信息 。
•   行动空间：包括 search[entity] (搜索实体)、lookup[string] (在页面内查找字符串) 和 finish[answer] (给出最终答案) 。
核心结果与观察：
•   ReAct 优于 Act (纯行动)：ReAct 在两个任务上都显著优于 Act-only 基线 。这证明了在引导行动和综合信息方面，推理（Thoughts）至关重要 。
•   ReAct vs. CoT (纯推理)：
◦   在 Fever 上，ReAct 优于 CoT ，因为 Fever 任务对事实的精确性要求极高，ReAct 的外部信息检索能力是关键优势
◦   在 HotpotQA 上，CoT 略微领先于 ReAct 。
•   **深入分析 **：研究人员手动分析了 200 个案例，发现：
◦   CoT 的主要失败点：幻觉 (Hallucination) 。56% 的 CoT 失败案例源于模型编造了错误的事实。
◦   ReAct 的优势：ReAct 更加扎实、可信 ，几乎没有幻觉导致的失败 (0%) 。
•   ReAct 的主要失败点：推理错误 (Reasoning error) 和 搜索错误 (Search result error) 。ReAct 的结构化约束有时会限制其推理的灵活性 (导致 47% 的推理失败) ，或者因为搜索不到有效信息而偏离轨道 (导致 23% 的搜索失败) 。
•   ReAct + CoT-SC 结合表现最佳：
◦   研究人员提出了两种结合策略（例如，当 ReAct 无法在N步内返回答案时，回退到 CoT-SC）。
◦   这种结合了内部知识 (CoT) 和外部知识 (ReAct) 的方法，在两个数据集上的表现都显著优于单独的 CoT-SC 或 ReAct 。
•   Finetuning (微调) 结果：
◦   在使用小型模型 (PaLM-8B/62B) 时，提示 (Prompting) ReAct 的效果很差，因为小模型难以同时学习推理和行动
◦   但惊人的是，在使用 3000 个 ReAct 轨迹进行微调 (Finetuning) 后，ReAct 成为了表现最好的方法 。
◦   微调后的 PaLM-8B (ReAct) 甚至超越了所有 PaLM-62B 的提示方法；微调后的 PaLM-62B (ReAct) 超越了所有 PaLM-540B 的提示方法 。这表明 ReAct 教授的“如何（推理并）行动以获取信息”是一种更具泛化性的技能，而不是像 CoT 那样教模型“记忆（可能虚假的）知识”。
4. 实验 2：决策制定任务 (ALFWorld, WebShop)
这部分测试 ReAct 在需要长程规划和与复杂环境交互的任务上的能力。
•   ALFWorld：一个基于文本的模拟家庭环境游戏 。智能体需根据高级目标（如“把一个干净的盘子放到桌上”）执行一长串（可能超过50步）的动作 。这需要常识推理（例如，盘子可能在橱柜里，清洁需要去水槽）。
•   WebShop：一个模拟的在线购物网站环境 。智能体需根据用户指令（如“我想要一个带抽屉的床头柜，价格低于140美元”），通过搜索、点击、选择选项等动作，最终购买到正确商品 。
核心结果与观察：
•   ReAct 显著优于 Act：在 ALFWorld 上，ReAct (最佳 71% 成功率) 远超 Act (最佳 45%) 。在 WebShop 上，ReAct (40.0% 成功率) 也远超 Act (30.1%)。
•   ReAct 优于 SOTA 基线：
◦   在 ALFWorld 上，ReAct (71%) 显著超越了使用 10^5 专家轨迹训练的模仿学习代理 BUTLER (37%)。
◦   在 WebShop 上，仅使用单样本提示的 ReAct (40.0%) 就超越了使用数千条数据训练的 IL (29.1%) 和 IL+RL (28.7%) 方法 。
•   ReAct vs. Inner Monologue (IM)：
◦   研究人员还将 ReAct 与先前的 "Inner Monologue" (IM) 方法 72进行了对比。IM 的“独白”仅限于重申环境状态和目标 73，而 ReAct 的“思想”则包含灵活的内部推理（如目标分解和常识推理）。
◦   结果显示，ReAct (71%) 再次大幅超越了 IM 风格的提示 (ReAct-IM, 53%) 75，证明了灵活的内部推理对于决策制定的重要性。
65 结论 (Conclusion) 与未来工作
结论：ReAct 是一种简单而有效的方法，它通过协同语言模型中的推理和行动，在知识密集型任务和决策制定任务上均取得了卓越的性能，并产生了更具可解释性的决策轨迹 。
局限与未来：
局限：在复杂任务中，仅靠少样本提示（in-context learning）有其局限性，因为上下文长度有限 。
未来方向：
•   微调：在 HotpotQA 上的初步微调实验显示了巨大潜力 ，未来需要更高质量的人类标注数据 。
•   扩展：将 ReAct 扩展到多任务训练 。
•   结合 RL：将 ReAct 与强化学习等范式结合，可能解锁 LLM 更大的潜力 。
附录中的额外亮点 (Appendix Highlights)
获取最新知识：附录中的一个案例 (Figure 4) 展示了 ReAct 的一个关键优势 。当被问及一个酒店的房间数量时，数据集的标签（2,664）已经过时了。CoT 和 Standard 方法都给出了错误或过时的答案 。只有 ReAct 通过实时搜索 API，获取了最新的正确答案（3,104），并准确地完成了推理 。
人机协同：附录 (Figure 5) 还展示了 ReAct “人-在-环路” (human-in-the-loop) 的潜力 。在一个 ALFWorld 任务中，ReAct 因为一个错误的“思想”（幻觉）而卡住 。人类观察者仅仅通过编辑这个错误的“思想”（例如，删除幻觉部分，并添加提示），ReAct 就能立即修正其后续的行为并成功完成任务 。这种通过编辑“思想”来即时纠正模型行为的能力，为人类对齐 (human alignment) 和人机协作开辟了新的可能性。
