DeepSeek 稀疏注意力机制 （NSA & DSA）,2025
今天我们来聊聊 DeepSeek 最近发布的 V3.2 模型及其技术报告中一个非常值得关注的亮点——那就是他们将稀疏注意力机制正式应用到了模型训练中，提出了 DeepSeek 稀疏注意力，简称 DSA。
了解大模型行业的朋友应该都知道，作为现代大语言模型基石的 Transformer 架构，它有一个核心痛点，就是它的“自注意力”机制。这个机制的计算复杂度与输入内容的长度——也就是 Token 序列长度——呈二次方关系。简单来说，如果你的输入长度翻倍，计算量和显存需求就会增长大约四倍。这就构成了严峻的计算和显存瓶颈，极大地限制了模型处理长文本的能力。
为了解决这个问题，DeepSeek 其实早在今年 2 月就发表了一篇名为《原生稀疏注意力》的论文，提出了 NSA，也就是 Native Sparse Attention。这是一种原生可训练的稀疏注意力机制。而在最近发布的 DeepSeek-V3.2 模型中，他们正式实装了这一机制，并将其命名为 DSA。在 V3.2 的技术报告中，他们详细描述了 DSA 的具体工程实现，比如使用了一个叫“闪电索引器”的东西来动态筛选 Token，成功将长上下文的计算复杂度从原来的 O(L²) 降低到了近似 O(kL)。
接下来，咱们就深入解析一下这套机制，看看它是如何从理论创新走向高效工程实践的。
首先，咱们得先明白为什么大家都在找替代方案，传统的全注意力机制到底卡在哪儿了？
标准 Transformer 模型中的全注意力机制，允许序列中的每一个词元（Token）都去关注所有其他的词元，以此来捕捉上下文关系。这种“全局审视”虽然好，但代价是巨大的。
第一个代价是计算成本的二次方增长。对于一个长度为 L 的序列，注意力机制需要计算一个 L 乘以 L 的注意力得分矩阵。这意味着，如果序列长度从 4k 增长到 64k，计算量将增长 256 倍。这种计算开销的急剧攀升，导致模型在处理长文本时，训练和推理的时间变得难以接受。
第二个代价是显存占用的急剧膨胀。在计算过程中，存储这个巨大的注意力矩阵会消耗大量 GPU 显存。更重要的是，在推理阶段，也就是模型逐个字生成的时候，需要缓存所有已生成词元的键（Key）和值（Value）向量，这就是我们常说的 KV 缓存。虽然 KV 缓存的大小是线性增长的，但随着长度增加，它对显存容量和带宽的压力也是巨大的，成了这一块的主要瓶颈。
这两个瓶颈共同构成了传统大模型在长上下文场景下的“效率墙”。
为了打破这堵墙，DeepSeek 团队提出了原生稀疏注意力（NSA）。
它的核心思想是设计一种硬件对齐且原生可训练的全新注意力架构。这个架构通过所谓的“分层稀疏策略”，模拟了人类高效阅读的模式。它把原本一次“通读全文”的重度计算，分解成了并行处理的三个轻量化分支。
第一个分支叫“粗粒度 Token 压缩”。这就像是我们快速浏览章节标题。它将历史序列划分为连续的块，并用神经网络把每个块内的所有 Token 压缩成一个“摘要”Token。这样模型就能以极低的成本快速扫描全局，形成宏观理解。
第二个分支叫“细粒度 Token 选择”。这就像是定位关键段落进行精读。它巧妙地复用刚才压缩出的中间分数，来给每个原始 Token 块的重要性打分。然后，模型仅选择分数最高的几个块进行精细计算。这种“块级选择”策略非常关键，它确保了 GPU 能够进行连续的内存读取，能很好地配合现代硬件（比如 FlashAttention）工作，把理论上的计算节省转化成实实在在的速度提升。
第三个分支叫“滑动窗口”。这就像是关注紧邻的上下文。它保留当前位置最近的一段历史 Token，确保对局部语法的连贯性和即时信息的捕捉。
NSA 通过这三个分支的协同工作，再由一个门控机制动态融合，实现了在保持全局、局部和关键信息感知的同时，把计算重心转移到了少数关键 Token 上。
理论有了，那在 DeepSeek-V3.2 模型里具体是怎么落地的呢？这就是 DSA，以及它背后的功臣——“闪电索引器”（Lightning Indexer）。
DSA 机制的核心就是一个名为“闪电索引器”的轻量级辅助模块。它的作用是在主注意力模块计算之前，进行一次快速、低成本的“全局扫描”，为每个查询 Token 评估所有历史 Token 的重要性，并生成“索引分数”。
这个索引器为了快，做了极致的优化：它使用极少数量的头和低维向量进行计算；它可以在 8 位浮点数（FP8）精度下运行，显著降低显存占用；它还用了计算开销极低的 ReLU 激活函数代替 Softmax。
整个 DSA 的工作流程可以概括为“先粗后精”：
第一步，快速预估。闪电索引器以极低成本对所有历史 Token 进行重要性预估。
第二步，动态选择。一个选择器根据分数，动态筛选出最重要的 Top-k 个历史 Token（在稀疏训练阶段这个 k 是 2048）。
第三步，精确计算。计算量巨大的主注意力模块，只在这 k 个被选中的 Token 上执行。从而将核心计算复杂度大幅降低。
大家可能好奇，这套机制听起来很厉害，实际效果到底怎么样？
综合技术文档的数据来看，DSA 和 NSA 在效率、精度和长文本处理能力上都表现卓越。
在效率方面，优势随序列长度增加而愈发显著。在训练阶段，相比于基于 Triton 优化的 FlashAttention-2，NSA 在处理 64k 长度序列时，实现了高达 9.0 倍的前向传播加速和 6.0 倍的反向传播加速。
在推理成本上，在 H800 GPU 集群的评估中，DSA 的解码成本几乎不受序列长度影响，稳定在每百万 Token 约 0.4 美元；而全注意力模型的成本则随序列增长线性增加，在 128k 长度时达到了约 2.4 美元。
在模型精度方面，得益于“原生可训练”的特性，DSA 模型在多数基准测试中与全注意力版本持平，甚至在部分任务上表现更优。
特别是在长文本与复杂推理能力上，DSA 表现亮眼。在“大海捞针”测试中，NSA 模型在 64k 上下文下能实现完美检索。在长文本基准 LongBench 上，它的平均分显著高于全注意力基线。在 AIME 数学竞赛基准上，经过微调的 NSA 模型准确率远高于同样微调的全注意力模型，这表明它能更有效地捕捉长距离的逻辑依赖。
最后，咱们来总结一下 DSA 和 NSA 为什么能成。
首先，关键在于算法与硬件的协同设计。不同于以往许多仅在算法层面优化的稀疏注意力方法，NSA 和 DSA 从一开始就充分考虑了 GPU 的特性，采用了“块级选择”而非“Token 级选择”，这是实现真实硬件加速的核心。
其次，“原生可训练”模式的优越性得到了验证。通过在预训练阶段就引入稀疏性，模型学习到了比全注意力模式更优的信息筛选策略。这解释了为什么 DSA 模型不仅没有性能损失，反而在像 GSM8K、DROP、AIME 这样需要推理的任务上表现更好。这说明，强制模型“聚焦”于最关键信息，可能反而有助于它发展出更强大的推理能力。
